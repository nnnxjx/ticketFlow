# TicketFlow API（步骤 2–3 已实现部分）

后端启动后访问：

- Swagger UI：`http://127.0.0.1:8080/swagger-ui.html`
- OpenAPI JSON：`http://127.0.0.1:8080/v3/api-docs`
- 健康检查：`http://127.0.0.1:8080/actuator/health`

所有业务接口使用 `/api/v1` 前缀。成功响应结构为 `code/message/data/requestId`，响应头也包含 `X-Request-Id`。受保护接口由 Spring MVC `AuthInterceptor` 校验登录态；在 Swagger 的 **Authorize** 中填入登录返回的原始 JWT，实际请求头为 `Authorization: <token>`，不加 `Bearer`。主办方数据归属由 Service 继续校验。

| 方法 | 路径 | 鉴权 | 用途 |
| --- | --- | --- | --- |
| `POST` | `/api/v1/auth/register` | 否 | 手机号与密码注册；密码至少 8 位 |
| `POST` | `/api/v1/auth/login` | 否 | 登录并获取 JWT；本地 `dev` 配置下暂不过期 |
| `GET` | `/api/v1/auth/me` | 是 | 获取当前账号 |
| `POST` | `/api/v1/organizers` | 是 | 创建主办方，当前账号成为负责人；每账号限一个 |
| `GET` | `/api/v1/organizers/me` | 是 | 获取当前账号负责的主办方 |
| `GET` | `/api/v1/system/ping` | 否 | 基础连通性检查 |

注册示例：

```json
{"phone":"13800138000","password":"examplePassword123"}
```

登录示例：

```json
{"phone":"13800138000","password":"examplePassword123"}
```

创建主办方示例：

```json
{"name":"城市音乐节主办方"}
```

本地 `dev` 配置的 JWT 暂不过期，仅用于测试；其他环境默认 2 小时过期。当前 JWT 无服务端撤销列表。“退出登录”由客户端删除令牌实现；禁用账号后，后端会在后续请求中拒绝其令牌。真实上线前还应补充登录限流、令牌撤销/刷新策略及更完整的审计能力。

## 演出与商品管理

下列管理接口均需要原始 JWT；后端根据当前登录用户查找其唯一的主办方，无需在路径中传主办方 ID。越权资源返回 404。草稿场次删除时在同一事务删除关联票档或场次座位；已有订单的场次不可删除。开售后不能随意修改价格、容量、场次模式或座位映射。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST/GET` | `/api/v1/organizer/events` | 创建/列出当前主办方演出 |
| `PUT/DELETE` | `/api/v1/organizer/events/{id}` | 修改/删除草稿演出 |
| `POST` | `/api/v1/organizer/events/{id}/publish` | 发布演出，要求至少一个已启用场次 |
| `POST` | `/api/v1/organizer/events/{id}/off-shelf` | 下架演出 |
| `POST/GET` | `/api/v1/organizer/events/{eventId}/sessions` | 新建/列出场次 |
| `PUT/DELETE` | `/api/v1/organizer/sessions/{id}` | 修改草稿场次；删除草稿场次及其票档/场次座位 |
| `POST` | `/api/v1/organizer/sessions/{id}/activate` | 启用场次；无座需有已启用票档，选座需已初始化座位 |
| `POST` | `/api/v1/organizer/sessions/{id}/stop` | 停售场次 |
| `POST/GET` | `/api/v1/organizer/sessions/{sessionId}/tiers` | 新建/列出无座场次票档 |
| `PUT/DELETE` | `/api/v1/organizer/tiers/{id}` | 修改/删除草稿票档 |
| `POST` | `/api/v1/organizer/tiers/{id}/activate` | 启用票档 |
| `POST` | `/api/v1/organizer/tiers/{id}/stop` | 停售票档 |
| `POST/GET` | `/api/v1/organizer/venues` | 新建/列出当前主办方场馆 |
| `GET/PUT` | `/api/v1/organizer/venues/{id}` | 查看/修改场馆 |
| `POST/GET` | `/api/v1/organizer/venues/{venueId}/seats` | 添加/列出物理座位模板 |
| `POST` | `/api/v1/organizer/sessions/{sessionId}/seats/init` | 按场馆模板初始化场次座位；请求体 `{"price":680.00}` |
| `GET` | `/api/v1/organizer/sessions/{sessionId}/seats` | 查看场次座位配置 |
| `PATCH` | `/api/v1/organizer/seats/{seatId}/price` | 草稿场次内修改座位价格；请求体 `{"price":1280.00}` |

## 公开查询

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/events` | 已发布演出列表 |
| `GET` | `/api/v1/events/{id}` | 已发布演出详情 |
| `GET` | `/api/v1/events/{eventId}/sessions` | 已启用场次 |
| `GET` | `/api/v1/sessions/{sessionId}/tiers` | 无座场次可售票档 |
| `GET` | `/api/v1/sessions/{sessionId}/seats` | 选座场次座位与价格 |

场次时间以 UTC 的 `yyyy-MM-ddTHH:mm:ss` 格式传入。所有场次都必须选择场馆；选座场次还需要先建立场馆座位模板。建议先创建场馆，再创建演出与场次、配置票档或场次座位、启用票档/场次，最后发布演出。步骤 4 将加入下单与库存交易接口。

无座场次请求示例：

```json
{"venueId":1001,"saleMode":"GENERAL","saleStart":"2027-01-01T09:00:00","saleEnd":"2027-01-05T18:00:00","startTime":"2027-01-06T19:00:00","endTime":"2027-01-06T22:00:00","checkinStart":"2027-01-06T17:00:00","checkinEnd":"2027-01-06T21:00:00"}
```

无座票档请求示例：

```json
{"name":"VIP","price":1280.00,"totalStock":500,"perOrderLimit":4,"perUserLimit":4,"saleStart":"2027-01-01T09:00:00","saleEnd":"2027-01-05T18:00:00"}
```

选座场次将 `saleMode` 改为 `ASSIGNED`；此模式不创建票档。场次草稿在初始化座位后可逐座改价，再启用场次。
